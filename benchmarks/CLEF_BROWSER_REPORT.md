# Clef-Browser 可行性评测

**结论：限定范围的只读导航原型可行，最终验证 9/9 完成；通用浏览器 Agent 仍需较多工程工作。**

2026-10-04，使用真实内网 Clef HTTP 服务、已登录的 ego-browser，以及仓库内标准库 Python 客户端。3 个已知目标任务各重复 3 次，顺序为 ABC / CBA / BAC；页面与服务未冷启动。每步一次 `choice`，阈值 0.6，最多 5 步、45 秒步骤间预算。完成必须同时满足模型 DONE 与独立目标 URL 检查。

| 任务 | 完成 | 端到端中位数 | 累计决策中位数 | 请求/次 |
| --- | --- | --- | --- | --- |
| GitHub → CONTRIBUTING.md | 3/3 | 4.82 s | 2.18 s | 2 |
| GitHub → src → cli.ts | 3/3 | 6.41 s | 3.20 s | 3 |
| X 搜索 → 指定 Jev 浏览器案例原帖 | 3/3 | 5.42 s | 2.05 s | 2 |

端到端包含初始页面加载、DOM 提取、HTTP 决策、后续导航和就绪等待；累计决策包含 Python 启动与网络，并非纯 GPU 时间。正式验证共 21 次决策，单次 0.57–1.62 秒。上下文较长的 19 候选页面约 1.6 秒，短完成判断约 0.6 秒。

## 实际发现

初版 X 测试选择了正确原帖，但在正文异步加载前返回 HANDOFF。补充正文就绪条件后，3 次重复均通过。失败记录保留在 [初版 X 轨迹](reports/clef-browser/x-browser-before-readiness.json)，最终轨迹与驱动 SHA-256 见 [原始结果](reports/clef-browser/results.json)。另外通过 10 项导航单元测试和 31 项现有协议/评测测试。

## 难度与适用范围

- **当前原型：中等，已实现。** 复用现有浏览器与客户端；代码负责链接范围、去重、防循环、完成验证和失败交接。
- **扩展表单/菜单：中等到较高。** 需要可靠元素定位、已知输入值、页面就绪条件和操作后的状态验证。
- **通用浏览器 Agent：高。** 长任务规划、视觉页面、登录、提交权限、网站变化和恢复策略均超出本原型。

本实验只验证已知目标的链接导航，没有大模型基线，因此**不能据此宣称浏览器任务加速倍数**。也未测开放式搜索、长文理解或任意网站成功率。24 个链接与 1,800 字符正文的预算可能遗漏目标，较长上下文还会增加服务延迟。

复现入口：[benchmarks/clef-browser.mjs](clef-browser.mjs)；安装与调用：[浏览器模块说明](../skills/ego-clef/references/browser.md)。在同一个 TaskSpace 中调用 `trial(page, taskIndex, repeat)`，完成九次后调用 `summarize()`；环境变量提供端点，报告不保存端点、密钥或完整正文。

## 默认接入验证

参考 [ego-jev](https://github.com/ZephyrDeng/ego-jev) 的 Agent 内部循环模式，增加一次性本机配置与浏览器技能路由提示，正常任务不要求用户点名模型或查看技术日志。清除浏览器脚本的 `CLEF_BACKEND_URL` 后，两个中文目标均通过：贡献指南 3.16 秒、X 原帖 3.38 秒（导航循环耗时，不含初始页面加载）。记录见 [默认入口验证](reports/clef-browser/default-routing.json)，本地 33 项 Python 与 14 项 Node 测试通过。

此验证证明配置发现和简化入口可用；技能自动选择依赖宿主加载技能，没有对所有浏览器 API 做底层拦截。原有 9 次评测与本节使用不同驱动版本，分别保留哈希。
